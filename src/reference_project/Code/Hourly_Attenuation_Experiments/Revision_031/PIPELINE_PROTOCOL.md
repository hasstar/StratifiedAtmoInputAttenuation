# TabM 分层与 RFE 顺序执行细则

本文件落实已冻结 PROTOCOL.md，不改变搜索候选、验证目标、训练预算或全量研究范围。新增执行代码独立封存，不修改正在运行的搜索代码。正式顺序：5个全156候选及QA → 1024种层组合 → 156到1独立RFE → 训练内one-SE选择及独立QA → 官方验证/测试的描述性评价。

一个后台等待器仅等待已核验PID及创建时间的搜索进程退出，不训练、不联网。成功检查搜索QA/全156 QA及源码SHA后取得同一个OS写锁，在同一进程中继续训练。搜索失败、身份变化、锁冲突或缺文件均停止，不自行修改候选或跳过失败。等待器不是第二个训练worker；可以中断但不能重复启动。没有新建或修改定时任务。

每个输入集合有三个按北京时间日期隔离的训练内折和一个全训练角色。完全相同有序特征、配置、训练/检查键、轮数和种子可复用同一已验证权重；每个角色都记录新拟合或复用。全156正式角色直接引用选定候选在所选轮数的检查点：相同训练RNG/批次、无验证反向传播，后续固定轮数训练在该轮的状态与其相同。不存在把置零推理计为子集重训的做法。

层组合按1023、0…1022顺序执行，每个mask保留50基础特征。RFE每次从剩余集合删除一个列。RFE种子为SHA256(本阶段manifest指纹|k|fold|完整列名)前8字节的大端整数；仅在折外数据内部置换已经由折内训练预处理的单列。保存每列置换后的折外预测，独立实现重算每列RMSE、三折增量均值和删除结果；全部置换与模型重放不增加训练次数。负值保留，不把相关特征的置换重要性解释为因果贡献。

各状态在提交后必须通过标准库独立数值QA和检查点重放，才能删列/继续依赖链。每个fold保留所有天气组，但one-SE及RFE重要性使用折外overall RMSE，与既有Rev029定义相同。one-SE阈值=min平均CV RMSE+该状态三折样本标准差/sqrt(3)；层组合优先最少层，再CV RMSE、mask；RFE优先最少列，再CV RMSE、k。官方验证和测试只在两路径训练/选择QA之后评价，不反馈到选层/删列；此前已交付的全156描述性结果不改变本细则。

所有1180状态的逐小时预测、模型/预处理、每轮记录和SHA保存。5120个层上下文配对的指标差只作描述，不把上下文当独立实测重复。阶段数值完成不自动等于最终论文图表、与历史BiLSTM对照及交付包审核完成。两天是我设定的工期目标，不凭空承诺CPU上的4720个拟合角色必定按时完成；不因耗时私自采样mask、跳删RFE、改轮数或停止所授权的研究。

安全：本阶段0网络、0天气、0安装、0新自动化；E-SST/RMOP/NWP/MTS原状态不变。每状态前检查剩余磁盘至少8GiB，低于阈值停下保留成果。已有结果/失败不覆盖，中间恢复状态沿用搜索程序的可恢复约定。
