# Revision 024 — train-fold permutation RFE for the screened 156-column SVR-RBF

## Scientific question and fixed inputs

Starting from Revision 023's QA-passed 156 weather columns (50 base, 106 pressure-level), determine how estimation error and pressure-level retention evolve when one input column at a time is removed and the **same RBF-SVR learning rule is refitted**. No layer, column, number of columns or favorable result is required to survive. This is a model-dependent predictive screen, not evidence that a variable causes attenuation.

Use the unchanged Signal_Detectability_Revision_003 partition: 2404 training, 343 validation and 687 test hours; target `clear_sky_attenuation_db`. No event, measurement-derived, quality, time, historical-power or historical-weather field is an input. The 156 columns and their order come directly from Revision 023's `feature_selection.json`. The frozen SVR configuration is the **all-156-column direct-refit configuration** selected within Revision 023's training-only grouped folds: `kernel=rbf`, `C=10`, `epsilon=0.1`, `gamma=scale`. This is distinct from the preliminary ten-family validation configuration and is fixed for all 156 feature counts. Each fit uses training-only median imputation and z-score scaling in a single pipeline. The full-156 refit must reproduce Revision 023's saved full-layer model predictions on training hours.

## Recursive elimination rule

For each feature count k=156,155,...,1, refit the pipeline from scratch in each of the same three calendar-day-disjoint training folds and once on all 2404 training hours. Save the complete ordered retained names, training-fold indices/hashes, all fold holdout predictions and scores, solver iteration counts, fitted full-train model, full-train predictions/scores, and source fingerprint. RBF-SVR has no intrinsic column coefficients, so use **held-out training-fold permutation importance**, not a nonexistent `coef_` or tree gain. For each retained column, shuffle only that column of each fold's holdout weather matrix once with a reproducible per-state/per-fold/per-column seed; compute `RMSE_permuted - RMSE_unpermuted` and average the three differences. Remove the column with the lowest mean increase, breaking exact ties by column name. Negative importances are permitted. Do not use validation, test or event labels to choose a deletion. The fold data may be used repeatedly for the elimination trajectory; selected-path fold scores are thus development estimates, not unbiased performance estimates.

Do not refit a candidate model for each possible deletion and do not call fixed-model zero masking RFE. The RFE cost is 156×(3 fold fits + 1 all-train fit)=624 new SVR fits, plus training-fold permutation predictions; there are 155 actual deletions. `k=1` is also refitted. Select one *predeclared* illustrative operating count using the training-fold one-standard-error rule: find the lowest mean holdout RMSE along the path, then choose the **smallest k** whose mean RMSE does not exceed that minimum plus its fold standard error. This choice and the entire feature path are frozen before validation/test evaluation. A full 156-to-1 test curve may be reported descriptively, but no test-optimal k may be promoted as a finalized model from these results.

## Evaluation and limits

After complete trajectory QA PASS, load the 156 saved full-train models without retraining and score the unchanged 343 validation and 687 test hours, saving every hourly prediction and overall/rain/dry-overcast/heavy-rain RMSE, MAE, bias and counts. Rain includes strong rain. Validation is a diagnostic here because the fixed SVR has no epoch-wise early stop; it cannot alter the frozen feature path or k. Test metrics are the final assessment of the predeclared operating count and descriptive trajectory. Test data were viewed in historical revisions, and train/test contain overlapping calendar days; this is neither a fresh blind test nor unseen-day generalization. Report these limits accurately. Do not alter Rev023, the dataset, source H5, source ERA5, Run_011 or any prior revision.

## Gates and completion

`prepare` freezes source SHA-256 hashes, column order, configuration, fold indices and protocol/code fingerprint. `run` is idempotent and resumes only under the same fingerprint; it writes 156 states and 156 model bundles. `verify-run` independently checks all states, 155 one-column transitions, 624 fits, saved hashes, model feature counts, recomputed fold scores and the full-156 parent-model equivalence, then freezes one-SE k. Only after QA PASS may `evaluate` load saved models and score validation/test; it cannot fit. `verify-evaluation` recomputes holdout scores from all 156 saved prediction records and checks the chosen k was frozen before holdout access. `report` writes tables and a readable result description. A living worker is inspected read-only and never launched twice. Failures resume from the last verified state with the same manifest; no source/old experiment files are modified.
